= Vert.x S3 Client

An asynchronous client for Amazon S3 and S3-compatible storage (DigitalOcean Spaces,
MinIO-compatible servers), based on Vert.x.

WARNING: The module is being rewritten. The API is incomplete and will change between versions.

== Creating a client

A client is configured with `S3ClientOptions`. The endpoint URI is the single source of scheme,
host and port, and the region is required. Here is DigitalOcean Spaces:

[source,$lang]
----
{@link examples.Examples#createForSpaces}
----

and a local MinIO-compatible server:

[source,$lang]
----
{@link examples.Examples#createForLocalMinio}
----

`S3Client.create` validates the options and throws `IllegalArgumentException` if they are invalid
(missing endpoint, region or credentials, ...).

Payload signing isn't configurable. Over HTTPS, request bodies are sent as `UNSIGNED-PAYLOAD`:
TLS protects them, and the signature still covers the method, path, query and headers. Over plain
HTTP, every body is signed with its SHA-256.

=== Addressing style

Buckets are addressed path-style by default (`https://host/bucket/key`), which every
S3-compatible server supports. *This differs from the AWS SDK default*, which is
virtual-hosted-style (`https://bucket.host/key`). To use virtual-hosted-style:

Static credentials are set with `setCredentials`. For credentials that rotate (e.g. a watched
Kubernetes secret), set a `S3CredentialsProvider` instead:

[source,$lang]
----
{@link examples.Examples#rotatingCredentials}
----

Secrets never appear in `toJson()` or `toString()` of the options.

== Contexts and threading

Every asynchronous method captures the caller's Vert.x context and completes its `Future` on
that context, whether the caller is an event-loop, worker or virtual-thread verticle. A client is
thread-safe and can be shared between verticles.

A client created inside a verticle is closed automatically when that verticle is undeployed,
like a Vert.x `HttpClient`. Otherwise it is closed together with its `Vertx` instance.

== Buckets

Create a bucket in the client's region:

[source,$lang]
----
{@link examples.Examples#createBucket}
----

Bucket names are checked before any request is sent: 3 to 63 lowercase letters, digits, dots and
hyphens, starting and ending with a letter or digit, no two adjacent dots, and not an IP address.
With virtual-hosted-style access over HTTPS, names containing dots are rejected, because
`bucket.with.dots.host` doesn't match the server's wildcard certificate. An invalid name fails with
an `S3ClientException`.

== Objects

Object keys are 1 to 1024 bytes of UTF-8 and may contain any character: the client encodes them on
the wire. An invalid key fails with an `S3ClientException` before any request is sent.

=== Uploading

Upload an object from a `Buffer`:

[source,$lang]
----
{@link examples.Examples#putObject}
----

with a content type and user metadata (sent as `x-amz-meta-*` headers; names are case-insensitive,
values are printable US-ASCII):

[source,$lang]
----
{@link examples.Examples#putObjectWithOptions}
----

Metadata values that aren't US-ASCII are rejected, not encoded. If you need them (e.g. Arabic file
names), URL-encode them yourself, or keep such data in the object key (keys accept any Unicode
character) or in your own database.

=== Downloading small objects

`getObject` buffers the whole object in memory, so it is for *small objects only*. An object larger
than `S3ClientOptions.maxBufferedObjectSize` (default 4 MiB) fails with an `S3ClientException`
pointing to `getObjectStream`, without its body being read.

[source,$lang]
----
{@link examples.Examples#getObject}
----

=== Streaming objects of any size

`getObjectStream` never buffers the object. Its future completes when the response headers arrive:
an error such as `NoSuchKey` fails it before any data is streamed. On success you get an
`S3ObjectStream`, a `ReadStream<Buffer>` with real backpressure that also carries the object's
metadata. It is handed out *paused*, and its handlers run on the context that called
`getObjectStream`. Pipe it to a file:

[source,$lang]
----
{@link examples.Examples#getObjectStreamToFile}
----

or to an HTTP response:

[source,$lang]
----
{@link examples.Examples#getObjectStreamToHttpResponse}
----

A single byte range can be requested with an HTTP `Range` value (`bytes=0-99`, `bytes=100-` or
`bytes=-100`):

[source,$lang]
----
{@link examples.Examples#getObjectRange}
----

IMPORTANT: Until it ends, an object stream holds a pooled HTTP connection. Read it to the end or
cancel it. A stream that is neither consumed nor cancelled never releases its connection.

[source,$lang]
----
{@link examples.Examples#cancelObjectStream}
----

== Errors

Failures are `S3Exception` instances. An `S3ServiceException` means the server answered with an
error response: it carries the HTTP status, the S3 error code (when the response has an error
document), and the request id to quote in support requests. Any other failure (connection, TLS,
an unreadable response, failing credentials, a closed client) is an `S3ClientException`.

== Using it next to the AWS SDK

`S3Client`, `S3Presigner` and `S3Exception` have the same simple names as AWS SDK v2 types. In a
file that uses both libraries, refer to one of them by its fully qualified name.
